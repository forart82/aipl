# AIPL Transpiler Guide: Pipeline A (TypeScript & React 19 JSX Lowering)

This guide documents **Pipeline A**, the official AIPL transpiler targeting modern JavaScript engines, TypeScript 5.x, and React 19.

---

## 1. Architectural Overview

AIPL features an early dual-backend bifurcation model at the **Canonical High-Level Intermediate Representation (Canonical HIR)**:
```
           ┌───────────────────────────────┐
           │      AIPL Source (.aipl)      │
           └───────────────┬───────────────┘
                           │ Lexer & Parser
                           ▼
           ┌───────────────────────────────┐
           │          AST Module           │
           └───────────────┬───────────────┘
                           │ Name Resolution & Typecheck
                           ▼
           ┌───────────────────────────────┐
           │         Canonical HIR         │
           └───────┬───────────────┬───────┘
                   │               │
  ┌────────────────▼──┐         ┌──▼────────────────┐
  │    Pipeline A     │         │    Pipeline B     │
  │ (TypeScript Tier) │         │ (Linear Wasm Tier)│
  │   React 19 JSX    │         │  Structure-of-Arr │
  └───────────────────┘         └───────────────────┘
```

Pipeline A translates Canonical HIR into a dedicated TypeScript Abstract Syntax Tree (`TsSourceFile`), subsequently emitted into human-readable, tree-shakeable, and strictly-typed TypeScript (.ts) and TSX (.tsx) source files.

## 2. Type System Mappings

AIPL guarantees zero implicit coercions and maps nominal and primitive types directly into their canonical TypeScript representations:

| AIPL Type | TypeScript Target | Semantic Guarantee |
| :--- | :--- | :--- |
| `int` | `number` | 64-bit integer lowered to JavaScript double precision floating / bigint in TS |
| `float` | `number` | IEEE 754 single precision float lowered to number |
| `num` | `number` | Double precision numerical primitive |
| `byte` | `number` | 8-bit unsigned integer |
| `str` | `string` | UTF-8 immutable string |
| `bool` | `boolean` | Strict boolean (`true` / `false`) |
| `void` | `void` | Absence of value |
| `nil` | `null` | Explicit absent reference |
| `Option[T]` | `T \| null` | Nullable union type |
| `Result[T, E]` | `Result<T, E>` | Discriminated algebraic error handling |
| `[T]` | `T[]` | Dynamic array |
| `[T; N]` | `T[]` | Fixed-length array |
| `(A, B)` | `[A, B]` | Strongly-typed tuple |
| `fn(A, B) -> C` | `(arg0: A, arg1: B) => C` | First-class callable signature |
| `struct Name:` | `export interface Name { ... }` | Structural object interface |
| `enum Name:` | `export enum Name { ... }` | Discriminated TypeScript enum |
| `type Alias = T` | `export type Alias = T;` | TypeScript type alias |

## 3. Side-by-Side Lowering Examples

### 3.1 Function Declarations & Statements

#### AIPL Source
```aipl
pub fn calculateTax(income: int, rate: float): float = income * rate

pub fn processUser(name: str, isActive: bool): str:
  let status = isActive ? "Active" : "Pending"
  ret "User: {name} ({status})"
```

#### Emitted TypeScript (.ts)
```ts
// Generated by AIPL Compiler (Pipeline A: Idiomatic TypeScript & React 19 Tier)
// Do not edit directly.

export function calculateTax(income: number, rate: number): number {
  return (income * rate);
}

export function processUser(name: string, isActive: boolean): string {
  const status: string = (isActive ? "Active" : "Pending");
  return `User: ${name} (${status})`;
}
```

### 3.2 Mutable Variables & Control Flow

AIPL strictly enforces explicit mutability (`let` is immutable, `mut` is mutable):

#### AIPL Source
```aipl
pub fn sumArray(items: [int]): int:
  mut total = 0
  for item in items:
    total += item
  ret total
```

#### Emitted TypeScript (.ts)
```ts
export function sumArray(items: number[]): number {
  let total: number = 0;
  for (const item of items) {
    (total += item);
  }
  return total;
}
```

---

### 3.3 Pattern Matching Desugaring

AIPL `match` statements compile into idiomatic TypeScript `switch` or if-else ladders:

#### AIPL Source
```aipl
pub fn classifyNumber(x: int): str:
  match x:
    0 => "zero"
    1 => "one"
    _ => "many"
```

#### Emitted TypeScript (.ts)
```ts
export function classifyNumber(x: number): string {
  switch (x) {
    case 0: {
      return "zero";
      break;
    }
    case 1: {
      return "one";
      break;
    }
    default: {
      return "many";
      break;
    }
  }
}
```

### 3.4 Lexical Closures (Zero Environment Object Overhead)

Unlike C or Wasm backends that must heap-allocate closure context structs (`__env`), Pipeline A emits native JavaScript arrow functions, preserving natural JS lexical scoping:

#### AIPL Source
```aipl
pub fn createMultiplier(factor: int): fn(int) -> int =
  (x: int): int => x * factor
```

#### Emitted TypeScript (.ts)
```ts
export function createMultiplier(factor: number): (x: number) => number {
  return (x: number): number => (x * factor);
}
```
> **Key Architecture Invariant**: Notice `factor` is captured directly through JavaScript's native lexical scope. Zero synthetic `__env` structures, zero wrapper classes, zero runtime indirection.

### 3.5 Native `async`/`await`

AIPL functions marked `async` lower directly to ECMAScript `async function` and native Promises:

#### AIPL Source

```aipl
pub async fn fetchData(url: str): str:

```

```ts
export async function fetchData(url: string): Promise<string> {
```

## 4. React 19 JSX & UI Component Lowering

AIPL natively models reactive user interfaces using declarative `component` blocks, dot-class selectors (`div.card.p-4.flex`), and event directives (`@click: onLogout`).

### 4.1 Functional Component Parity & Dot-Class Selectors

#### AIPL Source
```aipl
pub component Card(title: str):
  div.card.p-4.flex [
    span.title [ title ],
    button.btnPrimary [ @click: onLogout, "Logout" ]
  ]
```

#### Emitted TSX (`JsxMode::Jsx`)
```tsx
export interface CardProps {
  title: string;
}

export function Card({ title }: CardProps): React.ReactNode {
  return (
    <div className="card p-4 flex">
      <span className="title">{title}</span>
      <button className="btnPrimary" onClick={onLogout}>Logout</button>
    </div>
  );
}
```

#### Emitted Pure React 19 Runtime (`JsxMode::React19Runtime`)
```ts
import { jsx as _jsx, jsxs as _jsxs } from "react/jsx-runtime";

export interface CardProps {
  title: string;
}

export function Card({ title }: CardProps): React.ReactNode {
  return _jsxs("div", {
    className: "card p-4 flex",
    children: [
      _jsx("span", { className: "title", children: title }),
      _jsx("button", { className: "btnPrimary", onClick: onLogout, children: "Logout" })
    ]
  });
}
```

### 4.2 Automatic List-Reconciliation Keys

In traditional React, forgetting to provide a `key` prop inside an iteration loop causes re-render performance degradation and console warnings. AIPL solves this at compiler level:

#### AIPL Source
```aipl
pub component UserList(users: [User]):
  div.userList [
    for user in users:
      div.userRow [
        span [ user.name ]
      ]
  ]
```

#### Emitted TSX (`JsxMode::Jsx`)
```tsx
export interface UserListProps {
  users: User[];
}

export function UserList({ users }: UserListProps): React.ReactNode {
  return (
    <div className="userList">
      {users.map((user) => (
        <div key={user.id} className="userRow">
          <span>{user.name}</span>
        </div>
      ))}
    </div>
  );
}
```

#### Emitted Pure React 19 Runtime (`JsxMode::React19Runtime`)
```ts
import { jsx as _jsx, jsxs as _jsxs } from "react/jsx-runtime";

export interface UserListProps {
  users: User[];
}

export function UserList({ users }: UserListProps): React.ReactNode {
  return _jsx("div", {
    className: "userList",
    children: users.map((user) => _jsx("div", {
      key: user.id,
      className: "userRow",
      children: _jsx("span", { children: user.name })
    }))
  });
}
```
> **Key Architecture Invariant**: The compiler detects that `user` is rendered inside an iteration tree and automatically synthesizes `key={user.id}` (or `key: user.id`), providing zero-defect list reconciliation out of the box.

## 5. Verification & Strict Typechecking

Every output emitted by `compiler/codegen_ts.aipl` (invoked via `aipl transpile <file.aipl> --target ts -o out.ts` or `aipl build <file.aipl> --ts -o out.ts`) is validated against the official TypeScript compiler:

```bash
bun x -p typescript tsc --noEmit --strict --jsx react-jsx output.tsx
```

The validation suite asserts:
1. Zero TypeScript compilation errors.
2. Zero implicit `any` violations (`--noImplicitAny`).
3. Strict null checks satisfied (`--strictNullChecks`).
4. Strict function types satisfied (`--strictFunctionTypes`).
5. All JSX intrinsic elements and React 19 JSX runtime calls correctly typed.
